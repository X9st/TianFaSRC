# Phase 6 验收记录

状态：核心 UI 已交付并通过本地验收（2026-11-27）。

## 用户流程

1. 管理员或 Operator 在任务页创建草稿，设置目标、Allow 范围、策略模式、并发与模型链；启动后可暂停、恢复、取消和人工唤醒规划。
2. 任务详情查看 Todo、Intent、Worker 独立预算、Agent Run/模型尝试、ToolCall、策略阻断、实时动态、资产覆盖与可选择的探索血缘图。图节点可追溯来源方向、Run 和工具调用。
3. 任务会话可询问数据库态势、追加高优先级目标、在草稿或暂停状态加入禁止事项、派发高优先级方向、纠偏 Worker。人工消息、系统回执和 Agent 消息合并展示，指令留存审计。
4. 任务文件页按任务和 Intent 浏览、文本预览、下载。服务端验证组织、角色、任务与 Intent；拒绝路径穿越、隐藏文件和符号链接。Viewer 无法读取工作区。
5. 策略与审计页展示全局并发和 Worker 硬上限、任务策略阻断及组织内追加式审计，敏感审计详情不直接展示。
6. 仪表盘展示任务状态、活跃 Worker、Finding 严重度、模型健康、Token/费用累计、最近 Activity。任务列表可筛选并对运行中任务批量暂停或取消，操作前说明影响并确认。
7. Finding/Traffic/Retest/Report 沿用 Phase 5 页面；报告证据版本变化时显示过期提示。

## 关键边界

- 用户不配置预算。Planner 为每个 Intent 分配和调整 Worker 模型回合、工具调用、Token 与时长额度；运行时服务端硬限制并保存每次 Run 的快照。Planner 可读取近期 Worker 的实际消耗以决定是否收敛。
- 任务 SSE 使用持久化事件 ID 续传。前端按事件 ID 去重，轮询作回退；Activity 历史与实时结果也按事件 ID 合并。
- 会话中的“询问态势”使用当前数据库计数生成回执，不假装为模型推理。新增禁止事项要求任务处于草稿或暂停状态，防止活动 Worker 在策略变更期间继续执行。

## 验证证据

- `TIANFA_TEST_DATABASE_URL=... make test`：所有 Go 测试、OpenAPI 漂移检查和前端 TypeScript 检查通过。
- `make build`：Next.js 静态页与 Go 服务构建通过。
- PostgreSQL 集成：迁移幂等、Worker 预算隔离、会话指令、工作区预览/下载、RBAC、审计与仪表盘查询通过。
- 工作区单测：路径穿越、符号链接、隐藏文件和控制字符文件名被拒绝。
- 浏览器：管理员登录后仅通过界面创建任务、询问态势、追加目标；桌面和 390px 窄屏检查新页面。移动端导航可横向滚动而整页无横向溢出，会话新消息按人工指令、系统回执顺序展示，控制台无错误。

## 交付边界

自动化 Retester Agent、代理非 GET/HEAD 流量、命令输出与截图作为 Finding 证据等仍属于后续能力，不把它们算作 Phase 6 UI 验收通过。完整发布加固与故障注入属于 Phase 7。
