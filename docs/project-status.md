# 天罚：已完成能力与剩余工作

> 更新于 2026-11-28；核对基线：`main`。本页按[核心规格](../全新自主安全验证平台-核心能力实现规格.md)、[需求追踪](requirements-traceability.md)和各 Phase 验收记录整理。`已实现`表示已有代码和相应测试，不等于整个产品通过最终发布验收。

## 当前结论

**Phase 0–6 的核心能力已经交付，Phase 7 正在加固与验收。** 天罚已有可操作的漏洞挖掘工作台：授权范围、双图资产与探索、Decomposer/Planner/Worker、真实工具、模型主备、流量、漏洞线索、不可变证据、人工复测和报告能够串成工作流。当前**还不能宣布规格全部完成或正式发布就绪**：第 17 章要求的六个完整 E2E、部分故障注入、参考环境性能、全面安全与可访问性审计，以及发布镜像工作流实跑仍未结束。

## 已完成什么

### 1. 可追溯的自主挖掘主线

- 任务保存目标、授权范围、约束、策略模式、并发和模型路由。Planner 创建方向，Worker 按单条 Intent 执行；Todo 支持依赖，图事件可唤醒规划器。
- 资产图保存跨任务资产，探索图保存 Goal、Intent、Fact、Finding 的来源和证明关系；模型口头声称完成不能直接改变目标状态。
- Worker 使用真实工具产生观察，ToolCall 记录输入、状态、策略结果、输出、用量及关联 ID。每个 Worker Run 有由 Planner 调整、服务端执行硬限制的独立额度；**用户不配置预算**，见 [ADR-0004](adr/0004-agent-managed-worker-budgets.md)。
- 模型主备链支持独立 Profile、限速、计量、熔断和故障转移。HTTP Stub 测试验证主 Profile 返回 402 后备用 Profile 接管，并分别记录尝试与用量。

### 2. 程序化边界与证据链

- Scope 在工具边界执行，HTTP DNS 解析、重定向和连接地址均被校验；工具结果按不可信观察处理。新增测试验证网页诱导越界与越界重定向被阻断，Worker 仍可继续范围内请求。阻断审计记录脱敏目标、解析 IP、规则和原因。
- Skill ZIP 有安全检查，MCP 工具需发现、启用并经 `skill.load` 解锁；命令工具默认关闭，仅在配置隔离镜像后开放。远端 MCP 的服务端次级网络出口仍需管理员自行约束。
- 普通流量与 Evidence 分别引用内容寻址 Blob。Finding 从草稿经人工复核确认；绑定证据后删除普通流量不会丢失证据。报告支持 Markdown、JSON 和含原字节的 ZIP 导出，读取与导出校验哈希。
- 复测记录、Verification 证据及结论已持久化；当前由人工采集和提交，**自动 Retester Agent 尚未接入**。

### 3. 工作台与运维基础

- 前端已有挖掘总览、任务、模型、资产、工具、会话、工作区、策略审计、线索、流量、复测和报告入口。待复核线索与已确认漏洞分开统计；任务动态通过 SSE 和历史事件 ID 合并。
- 桌面与 390px 窄屏已做浏览器视觉复查，未发现整页横向溢出或控制台错误；截图见 [Phase 7 计划](phase7-plan.md)。这还不是完整可访问性审计。
- Compose 冷备份涵盖 PostgreSQL、Blob、工作区、Skill 与密钥材料；隔离恢复演练用非空 Blob、加密凭据和工作区文件验证了哈希、引用计数、解密与服务就绪。
- CI 执行 Go 测试、`go vet`、竞态检测、OpenAPI 漂移检查、前端类型检查与构建、依赖审计和工作流 lint。本地 Buildx 已产出 SBOM 与来源证明；摘要签名发布工作流已配置但未实跑。

第 17.3 节的八项故障与竞态已有针对性测试：20 Worker 单 Lease、Planner 与人工相似方向并发、Finding 写入中断、Blob 孤儿回收、流式断线后工具仅执行一次、主备 402、数据库短断、Pause/Cancel/Shutdown 同发。四个精确 Kill 时点仍由独立进程测试覆盖，尚未组成一次完整浏览器重启验收。细节见 [Phase 7 计划](phase7-plan.md)。

最近一轮本地 `make test`、`make race`、`go vet` 与前端类型检查通过。开发机性能预检（10 vCPU、约 8 GB）测得：10 万资产过滤列表 P95 **2.30 ms**、1 万节点图与覆盖 P95 **23.25 ms**、50 活跃 Worker 暂停加恢复 API 周期 P95 **7.41 ms**；SSE 断线续传 1 万条无遗漏、无重复，首批 500 条 **6.78 ms**。这些数字只说明本机预检通过，**不是**规格要求的参考环境验收结果。

## 还差什么

### 发布阻断项

1. **六个完整 E2E。** 以真实浏览器、受控靶场、Fake LLM/MCP 和独立 PostgreSQL 串起第 17.4 节的验收步骤，并保留 UI、数据库、审计与报告一致的证据。
2. **故障注入收口。** 将已通过的四个精确崩溃时点接入完整 E2E，并补齐剩余竞态，核验重启后没有重复副作用、丢失数据或永久 `running`。
3. **性能正式验收。** 开发机预检已测 10 万资产、1 万探索节点、50 个活跃 Worker 控制 API，以及 1 万事件 SSE 续传；必须在规定的 **8 vCPU / 16 GB、同机 PostgreSQL** 环境重跑。还缺 **1 GB 普通流量清理与 Evidence 并行读取** 基线。
4. **安全、可访问性、可观测性。** 完成生产配置与权限/范围/Secret 审计、键盘与读屏等完整可访问性检查，并补齐规格 14.4 要求的 API、队列、模型、工具、Blob 和 PostgreSQL 指标。
5. **发布链实跑。** 在真实工作流中验证镜像推送、SBOM/来源证明、Cosign 签名及身份验证；完成部署与恢复演练后的最终 DoD 复核。

### 已知功能边界与规格缺口

- 自动 Retester Agent 尚无闭环，复测目前由人工采集新流量并提交结论。
- Finding 的命令输出、截图、文件哈希、日志等**非 HTTP 证据类型**尚未实现；这与规格 `REQ-ARCH-008` 的完整要求存在差距。
- 记录代理目前仅支持无正文 GET/HEAD。其他方法要先设计审批与 Scope 策略；远端 MCP 的次级请求不能由本进程强制检查，必须依赖可信服务端的网络出口约束。
- Worker 主动 Trace 工具与完整 settlement、精确费用限额仍未完成；当前已有 Trace 查询、运行状态、Token/工具/时长额度和聚合用量。 [需求追踪](requirements-traceability.md) 对部分图与 Worker 需求仍标为“部分实现”，最终验收前需要逐条对账。
- `web/package.json` 目前只有类型检查和构建脚本，尚无独立前端 lint 门禁；规格 DoD 中的 “Lint” 需要明确并补齐。

## 下一步建议

先把 E2E-04 至 E2E-06 和剩余故障注入做成可重复的独立测试，再跑 1 GB 清理并行场景；随后在参考环境复测性能，完成安全/可访问性/指标审计，最后执行镜像发布与完整 DoD。每项通过后更新[需求追踪](requirements-traceability.md)和[Phase 7 计划](phase7-plan.md)，再宣布 Phase 7 完成。
